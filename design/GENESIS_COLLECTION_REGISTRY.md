# BuildinZ Genesis collection registry

Recorded October 31, 2026 (America/Chicago). This is the canonical production plan for naming, token ordering and edition rarity. It extends—without replacing—`COLLECTION_CONSISTENCY_STANDARD.md`.

## Authority boundary

- **Owner-fixed:** 1,000 tokens; 10 neighborhoods; 5 identities per neighborhood; 20 editions per identity; three permanent stages; identity and base rarity persist through evolution and resale.
- **Existing owner canon:** Neon Heights name, five identity types/stage lineages, visual language and Neon Residences feature rules.
- **Delegated production decisions:** adoption of the nine Foundation Blueprint working neighborhood themes, all non-Neon stage names, deterministic token ordering and rarity allocation.
- Delegated decisions are canonical for production but are not described as earlier owner approvals.

## Stable identity types

Every neighborhood uses the same five stable types: Residential, Retail, Technology, Entertainment and Landmark. Type never replaces the stage-specific mounted name.

## Edition and rarity allocation

Every identity has editions 1–20. Rarity is a stable cosmetic/base trait and does not change with evolution or resale.

| Edition numbers | Rarity | Per identity | Collection total |
|---|---|---:|---:|
| 1–8 | Common | 8 | 400 |
| 9–13 | Uncommon | 5 | 250 |
| 14–17 | Rare | 4 | 200 |
| 18–19 | Epic | 2 | 100 |
| 20 | Legendary | 1 | 50 |

Stable token ID formula:

`token_id = neighborhood_id × 100 + (identity_ordinal − 1) × 20 + edition`

Neighborhood IDs are zero-based in `COLLECTION_REGISTRY.json`; identity ordinals and editions are one-based. Token IDs are therefore contiguous 1–1000. Example: Neon Residences edition 1 is token 1; Crown of Neon identity edition 20 is token 100; Crimson Commons Landmark edition 20 is token 1000.

## Evolution and metadata rules

- Each token mints at Stage I.
- Evolution selects one of the same token's three stage assets; it does not mint a replacement token.
- Current stage is token state and must persist when ownership transfers.
- Neighborhood, identity, building type, edition and base rarity are immutable.
- The stage-specific name and image change together; metadata must never show a Stage II name with Stage I art.
- No placeholder image URI is permitted in production metadata.
- The committed 1,000-token manifest is registry-only until all three verified stage assets and permanent URIs exist.
- Rarity is cosmetic; it does not promise returns, yield or gameplay advantage.
